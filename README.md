# Държавен радар

Гражданско табло за отчетност на българската власт: обещания срещу действия, закони и законопроекти, законосъобразност, икономика и медии. Всеки факт има връзка към източника.

## Какво има в пакета

| Файл | За какво е |
|---|---|
| `index.html` | Самият сайт. Чете данните от папка `data/`. Бутонът „Обнови“ презарежда най-новите данни без кеш. |
| `data/*.json` | Всички данни, по един файл на раздел. |
| `update.py` | Скрипт, който тегли икономическите данни от Евростат (инфлация, БВП, безработица, дефицит, дълг). |
| `parliament.py` | Скрипт, който тегли списъка с нови законопроекти от parliament.bg (дата, номер, заглавие, вносители, комисии). |
| `.github/workflows/update.yml` | Пуска `update.py` всеки ден и записва промените в хранилището. |

## Публикуване в GitHub (около 5 минути)

1. Създайте ново хранилище в GitHub, например `darzhaven-radar` (Public, ако искате сайтът да е публичен).
2. Качете всички файлове от пакета: **Add file → Upload files**, плъзнете съдържанието на папката (включително скритата папка `.github`) и натиснете **Commit changes**.
   - Ако качването през браузъра пропусне `.github`, създайте файла ръчно: **Add file → Create new file**, име `.github/workflows/update.yml`, и поставете съдържанието му.
3. Включете сайта: **Settings → Pages → Build and deployment → Source: Deploy from a branch → Branch: `main` / `(root)` → Save**. След минута сайтът е на `https://<вашето-име>.github.io/darzhaven-radar/`.
4. Разрешете автоматичното обновяване да записва: **Settings → Actions → General → Workflow permissions → Read and write permissions → Save**.
5. Пробно пускане: **Actions → „Обновяване на данните“ → Run workflow**. След това в сайта натиснете „Обнови“.

## Как работи обновяването

- **Автоматично, всеки ден:** икономическите показатели от Евростат и списъкът с нови законопроекти от parliament.bg (раздел „Закони“, долу). Ако Евростат не отговори, старите стойности остават, а грешката се записва в `data/meta.json` (виждат се в „Методология и ограничения“ на сайта).
- **След преглед от редактор:** обещания, закони, констатации и медии. Тези оценки изискват човешка преценка и не се публикуват автоматично.
- **Бутонът „Обнови“** показва най-новото, което е записано в хранилището. Самото теглене от Евростат става в GitHub Actions. Може да се пусне веднага от раздел **Actions → Run workflow**.

## Как се добавят одобрени редове

1. Отворете съответния файл в `data/` в GitHub (например `data/findings.json`) и натиснете молива (**Edit**).
2. Добавете нов обект в списъка, със същите полета като останалите. Внимавайте за запетаите между обектите.
3. В `data/meta.json` сменете `updated` с днешната дата и `updated_by` с вашето име.
4. **Commit changes** с кратко описание, например „Добавено решение на КС № …“.

Всяка промяна остава в историята на хранилището: кой, кога и какво е променил. Това е публичен одитен път за данните.

### Полета по файлове

- `promises.json`: id, person, role, promise_date, promise, action_date, action, status (`kept` / `broken` / `contradiction` / `progress`), explanation, promise_url, action_url
- `bills.json`: id, title, number, submitter, stage, stage_date, effect_eur_m (число или null), effect_label, who_pays, who_gains, votes_for, votes_against (число или null), url
- `flags.json`: id, bill_id, flag, by, url
- `votes.json` (гласуване по групи): bill_id, vote (кое гласуване и дата), group, position (`за` / `против` / `въздържал се` / смесено), count (число или null), note (по желание), url
- `findings.json`: id, date, act, responsible, finder, kind (`court` / `audit` / `eu` / `oversight` / `allegation`), finding, binding, url
- `indicators.json`: id, indicator, value, unit, period, limit, warn (число или null), rule (`max` / `min`), limit_label, source, url
- `events.json`: date, event, institution, kind (`alarm` / `deadline` / `info`), url
- `media_scores.json`, `media_owners.json`, `media_findings.json`: виж съществуващите записи.

Датите са във формат `ГГГГ-ММ-ДД` или `ГГГГ-ММ`.

## Редакционни правила

- Като „нарушение“ се приема само констатация на съд или официален контролен орган. Твърдения на партии, НПО или медии се отбелязват като `allegation`.
- Имена на хора се посочват само когато източникът ги посочва като автори, вносители или подписали акта.
- При противоречие между думи и действия се добавя и позицията на отговорните (`explanation`).
- Без връзка към източник не се публикува нищо.

## Локален преглед

Браузърите не позволяват на страницата да чете JSON файлове, когато `index.html` се отвори директно от диска. За преглед на компютъра пуснете в папката:

```
python3 -m http.server 8000
```

и отворете `http://localhost:8000`.
